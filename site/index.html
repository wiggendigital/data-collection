        Method

        How the collector behaves

        • It says who it is

          Every request carries one plain name, so a site owner can see what is visiting and why.

        • It reads the site's rules first

          It fetches robots.txt once per site and never requests an address the file disallows.

        • It takes its time

          At most four requests at once, spaced a tenth of a second apart. The catalogue takes about two minutes, on purpose.

        • It retries with patience

          A timeout or a busy server gets three more tries, with a pause that doubles each time. If the server says how long to wait, it waits that long.

        • It checks every row

          Prices must add up, ratings must be 1 to 5, each product code must be unique. A row that breaks a rule is set aside with the reason, never dropped quietly.

        • It refuses to publish a bad run

          If fewer than 99% of the products come back, nothing is published. Yesterday's data stays up and the run is marked as failed.

        What I do not collect

        • Personal data about private people.
        • Anything behind a login, unless the account is yours and the terms allow it.
        • Sites whose terms or robots.txt forbid it. Social networks are the usual example.

        What is under the page

        • Python, with 51 automated tests. None of them touches the network.
        • A scheduler that runs the jobs every morning and rebuilds this page.
        • Plain files as output: CSV that opens in Excel, and JSON.
